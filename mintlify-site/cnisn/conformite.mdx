## 1. Profil de conformité d’une initiative

Toute initiative doit produire un profil indiquant :

- les principes applicables ;
- les capacités fournies ;
- les capacités consommées ;
- les contrats ART applicables ;
- les profils PTISN utilisés ;
- les services exposés ;
- les données échangées ;
- les sources autoritatives ;
- les preuves ;
- les dérogations.

------------------------------------------------------------------------

## 2. Dossier minimal

Le dossier comprend :

- note de concept ;
- rattachement aux value streams et capacités ;
- architecture fonctionnelle ;
- architecture des données ;
- architecture applicative ;
- architecture technique ;
- contrats d’échange ;
- matrice des responsabilités ;
- matrice des données ;
- modèle de sécurité ;
- politique de conservation ;
- stratégie d’exploitation ;
- stratégie de réversibilité ;
- résultats de tests ;
- déclaration de conformité.

------------------------------------------------------------------------

## 3. Critères de conformité

La revue porte notamment sur :

- autorité des données ;
- contractualisation ;
- versionnement ;
- sécurité ;
- minimisation ;
- résidence ;
- portabilité ;
- qualité ;
- réconciliation ;
- exploitabilité ;
- continuité ;
- coût total de possession ;
- alignement stratégique.

------------------------------------------------------------------------

## 4. Homologation

Une initiative peut recevoir :

| Statut                       | Signification                          |
|------------------------------|----------------------------------------|
| **Non évaluée**              | Aucun examen formel                    |
| **En revue**                 | Dossier en cours d’instruction         |
| **Pilote autorisé**          | Mise en œuvre limitée et encadrée      |
| **Conforme sous conditions** | Écarts limités avec plan de correction |
| **Conforme**                 | Exigences applicables démontrées       |
| **Suspendue**                | Risque ou non-conformité majeure       |
| **Retirée**                  | Service ou système non autorisé        |

------------------------------------------------------------------------

## 5. Homologation conditionnelle

Une homologation conditionnelle doit préciser :

- les écarts ;
- les risques ;
- les mesures compensatoires ;
- le responsable ;
- l’échéance ;
- les conditions de retrait ;
- les preuves attendues.

------------------------------------------------------------------------

## 6. Réévaluation

La conformité doit être réévaluée :

- périodiquement ;
- après une version majeure ;
- après un incident critique ;
- après une nouvelle intégration ;
- après un changement de propriétaire ;
- après un changement de données ;
- à l’expiration d’une dérogation.

------------------------------------------------------------------------
