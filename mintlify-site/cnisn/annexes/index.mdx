## Objet

Les annexes du CNISN documentent les matrices de correspondance entre les quatre niveaux d'architecture et les règles de lecture qui conditionnent leur usage. Elles ne créent pas de normes nouvelles : elles rendent lisibles des relations que le corps normatif du niveau 2 déclare, et dont la projection seule permet à un tiers de les vérifier.

L'annexe A : Matrice principes-objets d'interopérabilité croise les 25 principes du CNISN avec les objets d'interopérabilité requis. L'annexe B : Articulation avec l'ARTSN rattache les huit familles d'objets d'interopérabilité aux réponses architecturales du niveau 3. L'annexe C : Articulation avec le PTISN énonce ce que le niveau 4 doit fournir pour satisfaire chaque capacité du CNISN. L'annexe D : Principes de lecture explicite les conventions de lecture des quatre niveaux, notamment la distinction entre autorité nationale et base physique unique. L'annexe E : Correspondance CAESN–CNISN projette le rattachement des objets sur les capacités CAP-01 à CAP-18 du niveau 1. L'annexe F : Articulation complète documente le flux descendant de la capacité métier vers le profil technique. L'annexe G : Matrice des types d'interopérabilité rend explicite la couverture des quatre types d'interopérabilité, technique, sémantique, organisationnelle et juridique, par les capacités du CNISN.

Ces matrices sont un rendu du référentiel d'architecture : les relations qu'elles portent sont inscrites dans le frontmatter des fiches canoniques, via les champs `maps_to` et `implements`. Une cellule vide ne traduit donc pas une information manquante dans le référentiel, mais l'absence de lien déclaré de ce type. Cette transparence est ce qui distingue une projection d'une source de vérité autonome.

## Liens

Les objets d'interopérabilité dont ces matrices projetent les relations sont recensés dans la partie II du CNISN, et les principes qu'elles croisent dans la partie I.
