## 1. Objet et périmètre

Le **profil PT-03 — Catalogue des services et registre des contrats** définit deux services de référencement nécessaires à l’interopérabilité : le catalogue national des services et le registre national des contrats.

Périmètre : référencement des services exposés, de leurs propriétaires, consommateurs, et des contrats (schémas, profils, API, événements) qui les décrivent.

## 4. Acteurs (Actors)

- **Éditeur de service (Service Publisher)** — initiative publiant son service et son contrat versionné.
- **Consommateur de catalogue (Catalog Consumer)** — médiateur (PT-02) ou initiative résolvant un service et son contrat.
- **Gouvernance des contrats (Registry Owner)** — tient le registre national et les règles de compatibilité/dépréciation.

*Référence — capacité CNISN mise en œuvre : [CAP-INT-06](../capacites/cap-int-06.md).
## 5. Transactions

| Transaction | Acteurs | R/O | Standard |
|----|----|----|----|
| T1 — Publication d’un service | Éditeur → Catalogue | R | Enregistrement de service versionné |
| T2 — Publication d’un contrat | Éditeur → Registre | R | OpenAPI / FHIR IG / AsyncAPI / JSON Schema |
| T3 — Découverte de service | Consommateur → Catalogue | R | Requête de découverte |
| T4 — Résolution de contrat | Consommateur → Registre | R | Récupération du contrat versionné |

R = requis ; O = optionnel (à définir si le dépôt ne précise pas).

*Référence — capacité CNISN mise en œuvre : [CAP-INT-06](../capacites/cap-int-06.md).
## 6. Content Modules

- **Enregistrement de service** : service exposé, propriétaire, consommateurs autorisés, environnements, niveaux de service, points d’accès, politiques de sécurité.
- **Enregistrement de contrat** : schémas, profils, API, événements, versions, extensions, règles de compatibilité, dépréciations.

## 7. Options

- **O1 — Registre** : registre national des contrats dédié, ou registre intégré au catalogue.
- **O2 — Formats de contrat** : OpenAPI (API REST), Implementation Guide FHIR (ressource de santé), AsyncAPI (interface asynchrone), JSON Schema (événement non-FHIR), CodeSystem/ValueSet/ConceptMap (terminologie).

## 8. Service national

Deux services distincts sont requis.

### Catalogue national des services

Répertorie :

- les services exposés ;
- les propriétaires ;
- les consommateurs autorisés ;
- les environnements ;
- les niveaux de service ;
- les points d’accès ;
- les politiques de sécurité.

### Registre national des contrats

Répertorie :

- les schémas ;
- les profils ;
- les API ;
- les événements ;
- les versions ;
- les extensions ;
- les règles de compatibilité ;
- les dépréciations.

Aucun produit national n’est encore retenu (**statut : à instruire**).

## 9. Formats et standards recommandés

| Type de contrat      | Format recommandé                      |
|----------------------|----------------------------------------|
| API REST générale    | OpenAPI                                |
| Ressource de santé   | Profil HL7 FHIR                        |
| Guide national FHIR  | Implementation Guide publié            |
| Événement non-FHIR   | JSON Schema                            |
| Interface asynchrone | AsyncAPI ou contrat équivalent         |
| Terminologie         | CodeSystem, ValueSet, ConceptMap       |
| Exemples et tests    | Ressources et jeux de tests versionnés |

*Référence — normes et standards CNISN : [01_cnisn/05_standards](../../01_cnisn/05_standards/index.md).
## 10. Exigences

Tout service entrant en production doit être référencé au préalable dans le catalogue, avec un contrat publié et versionné dans le registre.

## 11. Déclaration de conformité (Integration Statement)

Preuves exigées : contrat publié, version explicite, propriétaire, test de validation, politique de compatibilité, calendrier de dépréciation.

## 12. Articulation avec les autres profils

Le catalogue et le registre sont consommés par la médiation intra-secteur ([PT-02](pt-02.md)) pour la validation des contrats, et par le service d’échange interinstitutionnel ([PT-01](pt-01.md)) pour la description de service.

## 13. Limites et dépendances

Aucun produit national n’est encore retenu (**statut : à instruire**). Le profil dépend des profils FHIR et terminologiques métier pour alimenter le registre des contrats.
